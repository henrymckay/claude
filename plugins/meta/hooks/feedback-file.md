
# Skill feedback

When a skill from any plugin steered you wrong, said nothing where it should have, or contradicted another skill, or the user corrected you on something a skill should cover, append a dated entry to `~/.claude/skill-feedback.md` and carry on; file no issue.
Name the skill and section, what happened, what should have happened, and the kind of project.
Describe the shape of the case, never the project's data: the file is later copied into a tracker others read.
Record skill corrections there, not in memory, and edit a skill only in a `review-plugin` sweep, never mid-task.
