
# Skill feedback

When a skill from any plugin steered you wrong, said nothing where it should have or contradicted another, or the user corrected you on something a skill should cover, append a dated entry to `~/.claude/skill-feedback.md` and carry on; file no issue.
Name the skill and section, what happened, what should have happened and the kind of project; describe the shape of the case, never the project's data, since the file is later copied into a tracker others read.
Record it even for a project kept local or private, since the entry carries none of its data.
Never park feedback in the project's plan or notes, or in memory, where no sweep reads it; edit a skill only in a `review-plugin` sweep, never mid-task.
